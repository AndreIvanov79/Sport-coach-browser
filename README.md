# Sport Coach Browser

Три отдельных приложения с общим TypeScript-ядром, которые анализируют спортивное видео полностью на устройстве (MediaPipe Pose в Web Worker, без серверов и LLM):

- **Fitness Coach** — автоопределение упражнения (каталог из 37 упражнений, перенесён из qwen36), повторы, темп, глубина, провис таза, асимметрия, амплитуда рук, подходы.
- **Boxing Coach** — удары-кандидаты (разгибание с возвратом), гард второй руки в момент удара, разворот плеч, скорость, стойка, работа головы, удары ногами.
- **Rhythm Coach** — прыжки, равновесия, вращения и прогибы по свойствам тела, удержания, шпагаты и частичный ориентир D/E по правилам FIG.

Для каждого вида спорта собираются PWA, расширение Chromium и расширение Firefox — 9 сборок. Интерфейс на русском, английском и румынском.

## Быстрый запуск

Нужен Node.js 22.18+.

```bash
cd /home/ivan/Dev/sport-coach-browser
npm ci
npm run build        # Lite обязательно; Full и Heavy скачиваются, если доступны
npm run preview      # http://127.0.0.1:4173/fitness/pwa/ · /boxing/pwa/ · /rg/pwa/
```

PWA работает через service worker, поэтому после пересборки открытая вкладка показывает прежнюю версию из кеша, пока не нажать «Обновить» в баннере «Доступна новая версия приложения» (он появляется при следующей загрузке страницы). Страница версии 0.1, у которой баннера нет, переключается на новую сборку сама за пару секунд.

`npm run build:lite` собирает только с моделью Lite. SHA-256 всех моделей фиксируются в `assets-lock.json` при первой загрузке и проверяются при каждой сборке.

## Что нового в 0.2

- **Выбор спортсмена.** MediaPipe ищет до 3 человек; спортсмен выбирается автоматически (самый крупный) и отслеживается по положению, масштабу и цвету одежды (торс и бёдра), поэтому партнёр на лапах или в спарринге не «подменяет» спортсмена при пересечении. Если выбран не тот — «Выбрать спортсмена»: клик по человеку на кадре, отчёт пересчитывается без повторной обработки видео. Раньше кадры с тренером, партнёром на лапах или отражением в зеркале выбрасывались целиком.
- **Пропуски до 0,3 с заполняются** для счёта циклов и графиков (медианы и покрытие — только по видимым кадрам). Раньше один потерянный кадр раз в 1,5 с превращал 6 приседаний в 1.
- **Последовательное декодирование** через `requestVideoFrameCallback` с откатом на позиционирование (фоновая вкладка, старые браузеры). Время кадра — реальное время кадра видео.
- **Перенос логики qwen36**: метрики и выводы фитнеса и бокса, правило «ошибка только если повторяется», ранжирование по серьёзности, распознавание упражнения по предикатам, свойства элементов ХГ и профили распознавания с семействами FIG.
- **Ракурс** (спереди / сбоку / под углом) с предупреждением, когда метрика в этом ракурсе ненадёжна.
- **Live-тренировка**: скелет и счёт в реальном времени, проверка кадра («всё тело в кадре»), обратный отсчёт, голосовые подсказки (только локальные голоса системы — сетевые не используются), запись и отчёт сразу после остановки.
- **Плеер для разбора**: углы у суставов, замедление 0,25×/0,5×, шаг по кадрам (← →), весь экран вместе со скелетом (кнопка в углу видео или F), курсор и переход по клику на графике, отметки циклов, ударов и элементов.
- **Отмена** даёт частичный отчёт по обработанной части.
- **История v2**: компактное хранение точек, динамика показателя по тренировкам, сравнение двух отчётов, импорт JSON, прикрепление исходного видео к сохранённому отчёту, запрос постоянного хранения.
- **PWA**: баннер «Доступна новая версия», иконки из qwen36 (включая maskable), ярлык Live, модели Full/Heavy кешируются по требованию.
- **Модели Lite / Full / Heavy** на выбор; `?cpu` в адресе принудительно включает CPU-делегат.

## Расширения

Chromium: `chrome://extensions` → режим разработчика → «Загрузить распакованное» → `dist/<спорт>/chromium`.
Firefox: `about:debugging#/runtime/this-firefox` → «Загрузить временное дополнение» → `dist/<спорт>/firefox/manifest.json`.
Разрешений на сайты и content scripts нет; модель, WASM и код внутри пакета.

## Проверки

```bash
npm run check        # TypeScript strict
npm test             # 30 тестов: ядро, виды спорта, интерфейс, словари
npm run e2e -- --fixtures work/fixtures   # браузерный прогон на реальных роликах (Playwright)
```

E2E берёт `work/fixtures/cases.json` и ролики VP9/WebM (Chromium без проприетарных кодеков не декодирует H.264). Результаты и скриншоты — `artifacts/e2e/`. Подробности и последние результаты — `docs/verification.md`. CI: `.github/workflows/ci.yml`.

## Границы анализа

- Все углы — проекции в плоскости кадра; это не калиброванная 3D-биомеханика.
- Счёт — полные наблюдаемые циклы; удары — разгибания с возвратом, а не подтверждённые попадания.
- ХГ: D учитывает только распознанные трудности тела без предмета (базовая стоимость семейства FIG), E — только наблюдаемые сбавки (удержание равновесия < 1 с, статика ≥ 4 с); шпагат по 2D-углу помечается как кандидат для проверки. A, DA, техника предмета и потери равновесия не оцениваются. Итоговый балл не рассчитывается.
- Модель Lite быстрая, но в предельных позах ХГ (кольцо, шпагат в равновесии, ноги за головой) «складывает» ноги и теряет опору: такие элементы часто не распознаются. Для ХГ лучше Full или Heavy. Фуэте и пируэты на полупальцах в 2D трудно отличить от маленьких подскоков; внутри серии вращений короткие низкие «полёты» считаются подъёмом на полупальцы.
- Мелкая фигура в кадре или контровой свет дают низкое покрытие — отчёт честно сообщит, что данных мало.
- Нет серверов обработки, LLM, аккаунтов, оплаты и аналитики.

## Структура

- `src/core/` — трек спортсмена, тело и мосты пропусков, серии, циклы, сегменты, ракурс, отбор выводов, сборка отчёта.
- `src/sports/` — фитнес (+ каталог упражнений), бокс, ХГ (+ каталог FIG из qwen36).
- `src/engine.ts`, `src/pose-worker.ts`, `src/analyzer.ts` — MediaPipe и декодирование.
- `src/ui/` — отчёт, история, live, выбор спортсмена, PWA, оверлей, графики. `src/i18n/` — ru/en/ro.
- `scripts/build.mjs` — модели, проверки, 9 сборок; `scripts/e2e.mjs` — браузерный QA; `scripts/qa-firefox.mjs` — расширение Firefox.

# Sport Coach Browser

Три самостоятельных приложения с общим TypeScript-ядром:

- **Boxing Coach** — одиночная техника: углы рук, положение кистей, наклон корпуса, наблюдаемые циклы разгибания локтя.
- **Fitness Coach** — приседания, отжимания, сгибание рук, наклоны и свободное движение: углы, амплитуда, циклы и их длительность.
- **Rhythm Coach** — художественная гимнастика: проекция раскрытия ног, линии коленей, углы бёдер и наклон корпуса.

В каждом приложении только свой вид спорта. Для каждого выпускаются PWA, расширение Chromium и расширение Firefox — **9 отдельных сборок**.

## Быстрый запуск

Нужен Node.js 22.18+ (для встроенного запуска TypeScript-тестов) или Node.js 24+. Зависимости зафиксированы в package-lock.json.

```bash
cd /home/ivan/Dev/sport-coach-browser
npm ci
npm run build
npm run preview
```

При первой сборке скачивается MediaPipe Pose Landmarker Lite. SHA-256 зафиксирован в assets-lock.json. Последующие сборки используют локальную копию.

После запуска preview:

- Fitness: http://127.0.0.1:4173/fitness/pwa/
- Boxing: http://127.0.0.1:4173/boxing/pwa/
- Rhythm: http://127.0.0.1:4173/rg/pwa/

Preview привязан к 127.0.0.1. Для телефона разместите соответствующую папку PWA на HTTPS-хостинге. Аналитический сервер не нужен.

## Расширение Chromium

1. Откройте chrome://extensions или edge://extensions.
2. Включите режим разработчика.
3. «Загрузить распакованное расширение» → нужная папка:
   - dist/boxing/chromium
   - dist/fitness/chromium
   - dist/rg/chromium
4. Нажмите иконку расширения: приложение откроется в отдельной вкладке.

У расширений нет host_permissions, content scripts и разрешений на доступ к сайтам. Модель, код и WASM входят в пакет. Выбор файла и камера работают внутри вкладки расширения.

## Расширение Firefox

1. Откройте about:debugging#/runtime/this-firefox.
2. «Загрузить временное дополнение».
3. Выберите manifest.json из dist/<спорт>/firefox.
4. Откройте приложение через кнопку расширения.

Временное дополнение удаляется после перезапуска Firefox. Для обычной постоянной установки и распространения понадобится подпись Mozilla. Подпись и публикация не выполнены.

Для Firefox используется background.scripts, для Chromium — background.service_worker. Длительный анализ выполняется в открытой вкладке приложения, а не в фоне расширения.

## PWA и работа без сети

1. Откройте PWA по HTTPS или localhost.
2. Дождитесь надписи **«Готово без интернета»**: она появляется после кеширования приложения, WASM и модели.
3. При поддержке браузера используйте «Установить» или его команду добавления на главный экран.
4. Теперь можно отключить сеть, перезагрузить приложение и анализировать локальное видео.

Каждый спорт имеет собственный scope, manifest ID, кеш и базу истории. При обновлении новая версия ждёт закрытия вкладок старой, чтобы код и модель не менялись посреди анализа.

## Что работает

- Локальный видеофайл до 10 минут / 1 ГБ; MP4, WebM и MOV в пределах поддерживаемых браузером кодеков.
- Запись камеры до 5 минут или 512 МБ без микрофона; анализ после остановки.
- MediaPipe в отдельном classic Web Worker, GPU с резервным CPU-режимом.
- Последовательное декодирование выбранных кадров; только один bitmap передаётся в обработку за раз.
- Частота выборки 10, 15 или 30 кадров/с; модель Lite; настраиваемый порог видимости.
- Плеер со скелетом, графики с разрывами при пропусках, переходы к отмеченным моментам.
- Явное отсутствие измерений при недостаточном покрытии.
- Сохранение отчёта и точек в IndexedDB только по кнопке. Видео не сохраняется.
- История с удалением отчётов, JSON, CSV и PDF через диалог печати.

Для графической подготовки кадров MediaPipe нужен доступный WebGL, в том числе при резервном CPU-режиме. При его отсутствии приложение показывает сообщение об ошибке. В проверенном Firefox без графического экрана WebGL был недоступен; в обычном графическом режиме анализ прошёл.

## Границы анализа

Это первая рабочая версия локального геометрического анализатора, а не полный перенос судейского/LLM-пайплайна qwen36.

- Углы рассчитаны в плоскости видео с учётом соотношения сторон. Это не измерение истинных 3D-углов.
- Числа confidence / visibility и высокий процент покрытия не гарантируют анатомическую точность.
- Метрика требует минимум 4 пригодных кадра и покрытие от 60%. Непригодные точки не интерполируются.
- Счёт показывает **полностью наблюдаемые циклы сустава** с достаточной амплитудой. Он не выдаётся за точное общее число повторений или ударов.
- Для бокса нет определения силы, попаданий, результата боя или оценки спарринга.
- Для гимнастики нет распознавания предметов, элементов CoP, оборотов, полёта или судейских баллов.
- Если MediaPipe обнаружил несколько людей, кадр исключается. Это не гарантирует, что модель заметила всех людей или сохраняет личность при смене сцены.
- Реальный темп обработки зависит от устройства. Быстрые движения и слабое освещение требуют отдельной проверки.
- Нет серверов обработки, LLM, аккаунтов, оплаты, Telegram-интеграции и аналитических трекеров.

## Проверки

```bash
npm test
npm run check
npm run build -- --qa
```

build сам выполняет проверку TypeScript и тесты расчётов. Браузерный QA дополнительно требует ffmpeg, установленный Chrome и короткое спортивное видео:

```bash
QA_VIDEO=/absolute/path/video.mp4 CHROME_PATH=/usr/bin/google-chrome npm run build -- --qa
```

QA проверяет три PWA в Chrome: загрузку приложения, мобильную ширину, настоящий MediaPipe, повторную загрузку и анализ без сети, историю, JSON, запись и анализ с тестовой камеры, отмену, отсутствие внешних запросов. Результаты и снимки — artifacts/. Фактические результаты проверки — docs/verification.md.

В scripts/qa.mjs есть локальный путь к тестовому ролику из qwen36 как запасной вариант; у другого разработчика нужно передать QA_VIDEO. Тестовый ролик и результаты со скелетом находятся в игнорируемом work/ и не включаются в установочные архивы.

Проверка расширения Firefox — отдельный scripts/qa-firefox.mjs. Требуются Firefox, geckodriver, графический DISPLAY и созданный основным QA файл work/qa/athlete.mp4. Пути можно задать через FIREFOX_PATH и GECKODRIVER_PATH; XVFB_PATH позволяет использовать виртуальный экран.

## Готовые архивы

```bash
npm run package
```

В artifacts/packages/ появятся девять ZIP с готовыми приложениями и sport-coach-source.zip с исходниками. Названия: boxing-, fitness-, rg- и суффиксы pwa, chromium, firefox. Распакуйте нужный архив в отдельную папку. Для PWA разместите содержимое на HTTPS-сервере, для расширения загрузите эту папку по инструкции выше.

В готовых приложениях уже есть модель и WASM. Архив исходников не содержит node_modules и модели: для воспроизводимой сборки используйте npm ci и npm run build.

## Структура

- src/profiles.ts — три отдельных спортивных профиля.
- src/core/ — метрики, полные циклы и объяснения по правилам.
- src/analyzer.ts — локальное декодирование и управление обработкой.
- src/pose-worker.ts — MediaPipe; bundling в classic Worker нужен его загрузчику WASM.
- src/storage.ts — независимая локальная история каждого спорта.
- src/app.ts, src/style.css — интерфейс, камера, отчёт и экспорт.
- scripts/build.mjs — модель, проверки, девять сборок, PWA-кеш и manifests.
- scripts/qa.mjs — воспроизводимая браузерная проверка.
- docs/architecture.md — решения и перенос из qwen36.
- docs/privacy.md — потоки данных и хранение.

Сборки и репозиторий не опубликованы в облаке или магазинах расширений.

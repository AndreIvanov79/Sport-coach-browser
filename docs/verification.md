## E2E на реальных роликах

Playwright + headless Chromium 153, модель Lite, CPU-делегат (`?cpu`), программный рендеринг SwiftShader. Ролики из qwen36, перекодированы в VP9/WebM (Chromium без проприетарных кодеков не читает H.264). Время — на облачной машине без GPU; на телефоне или ноутбуке с GPU будет иначе.

## Что исправлено по итогам прогонов

- **Подмена спортсмена в спарринге.** Добавлена цветовая подпись одежды (торс и бёдра) и её учёт в треке — только когда люди в ролике одеты заметно по-разному. Соседи в одинаковых купальниках и одиночный спортсмен отслеживаются, как раньше, по положению.
- **Ложные прыжки в ХГ.** Полёт не засчитывается, если нижняя нога «сложена» моделью (меньше половины обычной длины); короткие низкие «полёты» внутри серии вращений считаются подъёмом на полупальцы.
- **Пропущенные фуэте.** При 15 кадр/с поворот находится в профиль ~1 кадр — сглаживание профиля теперь только от 20 кадр/с; опора на полупальцах засчитывается по вертикальному положению тела. Ложные «вращения» при удержании кольца в профиль и при развороте на двух стопах отсекаются.
- **Скорость ударов** оценивается с 20 кадр/с (раньше с 24), поэтому ролики 24–25 кадр/с больше не теряют этот показатель.
- **Голос** — только локальные голоса системы (см. privacy.md).
- **Старая версия после сборки.** Service worker пилота (0.1) отдавал приложение из кеша и не умел обновляться, а новая сборка ждала нажатия «Обновить», которого в 0.1 нет — открывалась старая версия. Теперь новая сборка сама заменяет worker 0.1 и перезагружает его вкладки; e2e проверяет этот путь.
- Раньше (в ходе этой же работы): ложная перезагрузка при первой установке сервис-воркера, сверхмедленный GPU-делегат в программном рендеринге (`?cpu`), перенос карточек сводки, наложение подписей углов, шумное удержание 0,1 с.

## Известные ограничения

- **Lite в предельных позах ХГ** (кольцо, шпагат в равновесии, нога за головой) складывает ноги и путает стороны: такие равновесия часто не распознаются. Для ХГ лучше Full или Heavy.
- **Повторяемость.** Последовательное декодирование при ускоренном воспроизведении может брать немного разные кадры от прогона к прогону; на трудных роликах число найденных событий может отличаться на одно.
- **Спортсмен заслонён партнёром** — эти кадры честно считаются потерянными (в спарринге выше — 190 из 601), а не подменяются чужими.
- Распознавание формы прыжков в 2D приблизительно; итоговый балл FIG не рассчитывается.

## Что не проверялось здесь

- Firefox, Safari/iOS, Android и реальные телефоны; реальная камера (проверен только синтетический поток Chromium в версии 0.1); скорость с GPU-делегатом.
- Модели Full и Heavy: в этой среде нет доступа к storage.googleapis.com, сборка шла с `--lite-only`. `npm run build` у вас скачает их и зафиксирует SHA-256 в assets-lock.json.
- Точность подсказок на размеченной выборке; подписанные пакеты для магазинов расширений (нужны ваши аккаунты разработчика).

## Как повторить

```bash
npm ci
npm run build            # или build:lite
npm run e2e -- --fixtures work/fixtures
# без GPU (CI, виртуальная машина): E2E_CPU=1 npm run e2e -- --fixtures work/fixtures
node scripts/qa-firefox.mjs   # расширение Firefox в отдельном профиле
```

`work/fixtures/cases.json` описывает ролики и настройки; скриншоты и отчёты — в `artifacts/e2e/` (флаг `--dump` сохраняет полный отчёт JSON). Новый ролик для E2E:

```bash
ffmpeg -i clip.mp4 -an -c:v libvpx-vp9 -crf 34 -b:v 0 work/fixtures/clip.webm
```
